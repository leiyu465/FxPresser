# FxPresser 重构方案：原始一至七点版本

> 本文用于还原最初讨论的“一至七点”方案。  
> 后续已经修改的讨论稿保持不动，两份文档可并排对照。  
> 基准版本：`v2.4`

这次重构不再继续叠加实验代码，而是以“已验证可用”为边界重新组织。

## 一、保留的输入方式

只保留两种底层实现。

### 1. 前台键盘输入

- 使用 `SendInput`。
- 游戏已经有焦点时直接发送。
- “可靠优先”策略下，发送前自动恢复并激活游戏窗口。
- 这是目前最稳定的方式。

### 2. 共享状态消息

- 使用独立 Windows 消息线程。
- 开启自动运行时 Attach 一次，关闭时 Detach。
- 每次发送前读取当前键盘状态。
- 只修改当前模拟的 F 键。
- 发送 DOWN，等待释放间隔，再发送 UP。
- 释放时恢复该按键原来的状态，而不是直接清零。
- 用于不希望切换前台的场景。

### 3. 清理的旧实现

- `keyup only`。
- 各种 `PostMessageA` 测试组合。
- `lParam=0`。
- 双 KEYUP。
- 子窗口发送。
- `SendNotifyMessage`。
- `keybd_event`。
- 扫描码实验。
- 编号 2、9、13 等方法编号。
- 无法从界面触发的旧函数。
- `#if 0` 和“留待以后恢复”的废弃代码。
- 已失去意义的模式兼容配置。

Git 标签已经保存旧实现，需要时可以直接从历史恢复，不必继续保留在重构后的主代码中。

## 二、面向用户的运行策略

界面不再暴露 Windows API 名称，而是提供两种容易理解的策略。

### 1. 智能模式（默认）

- 游戏有焦点：使用前台键盘输入。
- 游戏没有焦点：使用共享状态消息。
- 不主动抢焦点。

### 2. 可靠模式

- 每次按键前自动恢复并激活游戏窗口。
- 使用前台键盘输入。
- 适合共享消息不生效的游戏环境。

### 3. 游戏置顶

“游戏置顶”作为独立选项：

- 只控制游戏窗口的 `HWND_TOPMOST`。
- 不定时抢焦点。
- 取消、切换窗口或程序退出时解除置顶。
- 可靠模式会在真正发送按键时激活游戏。

这样“置顶”和“焦点”不再混成一个含义不清的开关。

## 三、按键完整流程

### 1. 智能模式：游戏在前台

1. 调度器发现 F 键到期。
2. 确认游戏窗口当前拥有焦点。
3. `SendInput(KEYDOWN)`。
4. 计算释放间隔：设置值 ±2ms。
5. 结果小于 1ms则立即释放，否则启动一次性定时器。
6. `SendInput(KEYUP)`。
7. 更新该按键和全局调度时间。

### 2. 智能模式：游戏在后台

1. 调度器发现 F 键到期。
2. 将命令交给已 Attach 的共享线程。
3. `GetKeyboardState` 保存当前 F 键原始状态。
4. 只设置目标 F 键的按下位。
5. 发送 DOWN 消息。
6. 等待释放间隔。
7. 恢复该 F 键原始状态。
8. 发送 UP 消息。
9. 返回执行结果。

### 3. 可靠模式

1. 如果游戏最小化则恢复。
2. 必要时调用 `SetForegroundWindow`。
3. 在一个很短、有上限的窗口内确认焦点。
4. 成功后走前台 `SendInput`。
5. 激活失败时记录原因，不盲目把输入发给其他窗口。

## 四、调度器重构

目前时间逻辑散落在 UI 和发送函数中，建议集中到 `KeyScheduler`。

- 每个按键保存自己的下次到期时间。
- 全局间隔只负责限制任意两次触发。
- 公平轮询，避免 F1 长期挤占后续按键。
- 同一时间只允许一个模拟键处于按下状态。
- 发送失败不错误刷新成功时间。
- 关闭全局开关时：
  - 停止产生新任务。
  - 立即释放未释放按键。
  - 清空待处理任务。
  - 停止共享线程。
- 不在每次调度前调用 `IsWindow`。
- 开启时检查一次窗口。
- 发送 API 明确失败时，再自动停止并提示重新扫描。

## 五、代码结构

### 1. `GameWindowManager`

- 扫描窗口。
- 管理当前窗口选择。
- 激活、恢复和置顶。
- 判断窗口有效性。

### 2. `KeyScheduler`

- 管理单键间隔。
- 管理全局间隔。
- 公平调度。
- 管理启停状态。

### 3. `ForegroundInputBackend`

- 使用 `SendInput`。
- 管理 DOWN/UP 生命周期。

### 4. `SharedInputBackend`

- 管理独立消息线程。
- 管理 Attach/Detach。
- 保存和恢复键盘状态。
- 发送窗口消息。

### 5. `AutomationController`

- 管理智能/可靠策略。
- 选择具体输入后端。
- 处理错误。
- 管理运行状态。

### 6. `FxMainWindow`

- 只负责界面。
- 不再直接处理 Windows 输入细节。

## 六、界面优化

主界面建议精简为：

- 游戏窗口选择。
- 扫描按钮。
- 当前状态：已停止／运行中。
- 运行策略：智能／可靠。
- 游戏置顶。
- 大尺寸“开始／停止”按钮。
- F1～F10启用和间隔。
- 全局间隔。

高级设置折叠区：

- 释放间隔。
- 默认技能。
- 调试日志。
- 快捷键设置。

建议加入：

- 全局开始/停止快捷键，例如 `Ctrl+Alt+F12`。
- 紧急停止快捷键，例如 `Ctrl+Alt+F11`。
- 托盘图标。
- 托盘菜单显示运行状态。
- 状态栏显示最近一次执行：
  - `F3 · 前台键盘`。
  - `F5 · 共享状态`。
  - `激活游戏失败`。
- 开始运行后锁定窗口选择和关键配置，防止中途切换导致状态错乱。
- 调试日志继续只在窗口打开时产生，不写文件。

## 七、实施顺序

1. 建立重构分支。
2. 删除所有已验证无效的输入方式。
3. 抽离两个输入后端。
4. 重写调度器及按键释放生命周期。
5. 实现智能和可靠两种策略。
6. 重做置顶与焦点职责。
7. 精简主界面。
8. 加入全局快捷键和紧急停止。
9. 做以下测试：
   - 前台/后台。
   - 最小化/恢复。
   - 置顶开启/关闭。
   - 释放间隔为负数、0、1ms、27ms。
   - 多个按键同时到期。
   - 高频关闭全局开关。
   - 游戏窗口中途退出。
   - 真实键盘输入和鼠标双击。
10. 生成新的 32 位静态单文件版本。

建议把重构后的第一个版本定为 `v3.0`，并以 `v2.4` 标签作为完整回退点。
