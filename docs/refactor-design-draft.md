# FxPresser 重构方案（讨论稿）

> 基准版本：`v2.4`  
> 本文只用于确认重构方向，确认后再修改代码。

这次重构不再继续叠加实验代码，而是以“已验证可用”为边界重新组织。

## 一、代码结构

### 1. `GameWindowManager`

- 扫描游戏窗口。
- 保存当前选择。
- 检查前台与焦点状态。
- 恢复、激活和置顶游戏窗口。
- 处理窗口失效。
- 切换当前游戏窗口前，通知控制器关闭全局开关。

### 2. `InputModeManager`

- 程序启动时实例化一个独立对象，生命周期与主程序一致。
- 自动选择默认开启，程序启动时立即创建焦点检测线程。
- 独立维护“是否自动选择”“手动选择方式”和“当前有效方式”。
- 当前有效方式保存在类的线程安全成员变量中。
- 自动选择关闭时，下拉框变化直接写入手动选择方式和当前有效方式。
- 自动选择开启时，由该对象创建焦点检测线程，每隔 `100ms` 检查一次当前游戏窗口是否拥有焦点。
- 每次检测都从 `GameWindowManager` 获取当时的当前窗口，不缓存窗口句柄。
- 当前没有选择窗口或窗口已经不存在时，跳过本次检测，不修改当前模式。
- 游戏有焦点时，将当前有效方式写为“按键+手动窗口”。
- 游戏没有焦点时，将当前有效方式写为“共享消息”。
- 关闭自动选择时停止并销毁焦点检测线程，与全局开关状态无关。
- 只维护模式，不直接发送按键，也不直接操作界面。
- 对外提供 `currentMode()`，按键执行服务每次开始完整按键时调用该方法。

### 3. `TimeConfigManager`

- 程序启动时创建，线程安全地维护全局间隔、释放间隔以及 F1～F10各自的间隔。
- 界面修改时间后立即写入该对象，运行中的下一次读取直接生效。
- 对外提供 `globalInterval()`、`releaseInterval()` 和 `keyInterval(index)`。
- 使用方必须在真正需要时间值时调用读取方法，不能在构造时读取并长期缓存。

### 4. `KeyConfigManager`

- 程序启动时创建，线程安全地维护 F1～F10的启用状态。
- 界面可以在运行中修改，调度器每次循环时读取当前值。
- 不再包含“缺省技能”概念。

### 5. `KeyScheduler`

- 每次打开全局开关时创建独立调度线程，关闭全局开关后退出并销毁。
- 全局开关关闭期间不存在线程，也不进行循环。
- 按照 F1～F10 的固定顺序循环。
- 检查每个按键的启用状态和独立间隔。
- 在实际执行两个按键之间应用全局间隔。
- 到达执行时机时，只调用统一的按键执行接口。
- 不知道当前有几种按键方式，也不依赖任何具体按键实现类。
- 每次判断或等待时读取 `KeyConfigManager` 和 `TimeConfigManager` 的当前值，不保存时间配置副本。
- 只接收开始和停止命令，动态配置由对应配置对象自行维护。
- 将运行状态和执行结果通过信号发送给控制器。

### 6. `IKeyExecutor`

- 所有按键模拟方式共同实现的统一接口。
- 核心方法为 `execute(KeyRequest) -> KeyResult`。
- 一个 `execute()` 必须完成 KEYDOWN、释放间隔和 KEYUP 的完整流程后才能返回。
- `KeyRequest` 包含窗口和虚拟键等按键参数。
- 执行器在需要释放间隔时调用 `TimeConfigManager::releaseInterval()`，不缓存构造时的值。
- `KeyResult` 包含成功状态、实际方式和错误信息。

### 7. `SharedMessageKeyExecutor`

- 独立实现 `IKeyExecutor`。
- 管理独立 Windows 消息线程以及 Attach/Detach资源。
- Attach与全局开关保持一致，不根据当前按键模式按需创建。
- 一次完整按键只调用一次 `GetKeyboardState` 和一次 `SetKeyboardState`。
- 设置目标键为按下后发送 DOWN，等待释放间隔，再直接发送 UP。
- UP前不再次调用 `GetKeyboardState` 或 `SetKeyboardState`，也不恢复或清除目标键状态。

### 8. `AutoWindowKeyExecutor`

- 独立实现 `IKeyExecutor`。
- 每次执行前根据需要恢复并激活游戏窗口。
- 使用 `SendInput` 完成按下、释放间隔和释放。

### 9. `ManualWindowKeyExecutor`

- 独立实现 `IKeyExecutor`。
- 不主动检查或改变窗口焦点。
- 使用 `SendInput` 完成按下、释放间隔和释放。

### 10. `KeyExecutionService`

- 程序启动时创建，并持有三种 `IKeyExecutor` 的独立实例。
- 每次 `executeKey()` 开始时调用 `InputModeManager::currentMode()`。
- 根据模式找到对应的执行实例，再调用统一的 `execute()`。
- 一次执行开始后固定使用同一个实例，直到完整按键结束。
- 使用“模式到执行实例”的注册关系管理实现，不把方式判断写进调度器。
- 后续增加新方式时，只新增 `IKeyExecutor` 实现并注册到服务中。

### 11. `AutomationController`

- 持有并连接调度器、窗口管理器、模式管理器和按键执行服务。
- 将统一的按键执行服务提供给调度器。
- 打开全局开关时先启动共享消息线程并完成 Attach，再创建调度线程；不判断当前模式。
- 关闭全局开关时先停止调度线程，再 Detach并销毁共享消息线程。
- 处理启动、停止和异常。
- 向界面报告当前状态和执行结果。

### 12. `FxMainWindow`

- 只负责显示界面和接收用户操作。
- 不直接调用 `SendInput`、`SetKeyboardState` 或窗口消息 API。
- 不直接执行调度时间计算。

### 13. `GlobalHotkeyManager`

- 使用 Windows `RegisterHotKey` 管理一个全局开始/停止快捷键。
- 程序启动时读取并注册用户保存的快捷键。
- 提供设置对话框，让用户录入和修改快捷键组合。
- 修改时先验证新快捷键是否能够注册；成功后替换旧快捷键并保存配置。
- 注册失败时保留原快捷键，并明确提示冲突或注册失败。
- 快捷键触发行为与点击主界面的开始/停止按钮完全一致。

## 二、调度器重构

调度器是一次全局开关运行会话：打开全局开关时创建独立线程，并在该线程中维护一个按 F1～F10 固定顺序运行的循环；关闭全局开关时停止循环、退出线程并销毁对象。它不建立任务队列，也不计算复杂的到期集合。界面线程不参与循环，也不执行任何按键等待。

### 1. 基本流程

```text
从 F1 开始
  ↓
检查该按键是否启用
  ├─ 未启用：直接检查下一个按键
  └─ 已启用：继续检查独立间隔
                ↓
当前时间 - 该键上次执行时间 >= 该键设置的间隔？
  ├─ 否：直接检查下一个按键
  └─ 是：立即记录本次KEYDOWN调度时间
                ↓
       调用统一按键执行接口
                ↓
       记录结果日志，不改变调度
                ↓
          等待全局间隔
                ↓
        继续检查下一个按键
                ↓
F10 检查完成后重新回到 F1
```

### 2. 单键间隔

- 每个按键记录自己的上次 KEYDOWN 调度时间。
- 循环到该按键时，实时调用 `timeConfig.keyInterval(index)` 获取当前设置。
- 使用当前时间减去上次记录时间，时间差大于等于当前设置时才执行。
- 间隔尚未到时直接跳过，不等待，也不修改时间点。
- 第一次启动时，各启用按键都视为可以立即执行。
- 达到执行条件后，在调用按键执行服务之前立即记录当前时间。
- 无论执行成功还是失败，都保留这个时间点，不回滚、不重试。

### 3. 全局间隔

- 全局间隔表示按完一个按键后，到检查和执行后续按键前的等待时间。
- 调用一次完整按键执行单元后，无论成功还是失败，都等待全局间隔。
- 跳过未启用或间隔未到的按键时，不等待全局间隔。
- 全局间隔结束后，从刚才按键的下一个编号继续检查。
- 开始等待时调用 `dispatch.waitTime(timeConfig.globalInterval())`，不使用调度器构造时缓存的值。

### 4. 调用按键执行单元

- 调度器只持有统一的按键执行接口，不持有模式管理器和任何具体执行方式。
- 到达执行时机后，调度器构造 `KeyRequest` 并调用 `KeyExecutionService::executeKey()`。
- `KeyExecutionService` 负责读取当前模式、选择执行实例并完成整个按键。
- 调度器不参与模式选择、窗口激活、KEYDOWN、释放等待或 KEYUP。
- 按键执行服务完成整个按键过程后，将统一的 `KeyResult` 返回调度器。
- 调度线程等待的是一次完整按键操作的完成，界面线程不会被阻塞。
- 调度器不根据 `KeyResult` 改变时间、顺序、重试或停止逻辑。
- 成功与失败只发送给日志和界面状态层；只有失败日志使用红色显示，其余日志使用默认文字颜色。

### 5. 空循环控制

如果一轮 F1～F10 都没有按键可以执行，调度线程进行一次很短的可中断等待，避免持续空转占满 CPU。这个等待只属于内部扫描节流，不属于用户设置的全局间隔。

### 6. 停止

- 关闭全局开关时只设置“停止继续循环”的标志。
- 全局间隔和空循环等待可以被停止信号立即唤醒。
- 如果当前正在执行一个完整按键单元，不中断其释放间隔，也不额外补发 KEYUP。
- 当前按键单元正常完成并返回后，循环检查停止标志，不再执行下一个按键。
- 调度循环结束后退出线程，由控制器销毁本次运行创建的线程对象。
- 全局开关关闭期间不保留空闲调度线程。

### 7. 线程之间的职责

```text
界面线程
  ├─ 模式开关/下拉框变化 → InputModeManager
  ├─ 时间变化 → TimeConfigManager
  ├─ 按键启用变化 → KeyConfigManager
  └─ 全局开关打开：创建调度线程并提交运行配置
          ↓
AutomationController
          ↓
调度线程
  └─ 到达时机后调用 KeyExecutionService::executeKey()
          ↓
KeyExecutionService
  ├─ 调用 InputModeManager::currentMode()
  └─ 根据模式选择一个 IKeyExecutor 实例
          ↓
SharedMessageKeyExecutor
AutoWindowKeyExecutor
ManualWindowKeyExecutor
          ↓
将成功、失败和实际执行方式返回界面

全局开关关闭
  └─ 禁止继续循环 → 等待当前完整按键单元返回 → 退出线程 → 销毁线程对象
```

- 界面控件只能由界面线程访问。
- 调度线程不能直接读取复选框或输入框，通过线程安全的配置管理对象读取最新值。
- `InputModeManager` 在程序启动时创建，不由全局开关创建或销毁。
- 自动选择开关独立控制焦点检测线程的创建和销毁。
- 运行中修改自动选择开关或手动下拉框时，直接更新模式实例；下一次按键执行时读取新方式。
- 焦点检测线程只更新下一次按键要使用的方式，不改变已经开始的按键单元。
- 调度线程不直接更新界面，通过 Qt 信号报告状态和日志。
- 三种执行方式分别由独立类和独立实例维护自己的状态与资源。
- 调度器只依赖 `KeyExecutionService` 的统一调用，不因新增按键方式而修改。
- 调度器和执行器均不在构造时缓存间隔；在真正使用时间值时调用 `TimeConfigManager`。

## 三、保留的按键方式

界面保留原来的按键方式下拉框，共有三种可用方式。其中“按键+自动窗口”和“按键+手动窗口”共用 `SendInput` 后端，区别在于发送前是否主动激活游戏窗口。

### 1. 共享消息

- 使用独立 Windows 消息线程。
- 打开全局开关时 Attach一次，关闭时 Detach，与当前模式无关。
- 每次执行按键时调用一次 `GetKeyboardState`。
- 只把当前目标 F 键修改为按下状态，然后调用一次 `SetKeyboardState`。
- 使用 `SendMessageTimeout` 发送 DOWN，等待当前释放间隔，再发送 UP。
- UP前不再次读取或设置键盘状态，不恢复目标键，也不清除目标键按下位。
- 不主动切换游戏到前台。

### 2. 按键+自动窗口

- 使用 `SendInput`。
- 每次执行按键前检查游戏窗口。
- 游戏没有焦点时，先恢复并激活游戏窗口。
- 然后执行完整的按下、释放间隔和释放流程。

### 3. 按键+手动窗口

- 使用 `SendInput`。
- 不主动切换或激活游戏窗口。
- 直接执行完整的按下、释放间隔和释放流程。
- 由用户保证游戏窗口当前拥有焦点。

### 4. 清理的旧实现

- `keyup only`。
- 各种 `PostMessageA` 测试组合。
- `lParam=0`。
- 双 KEYUP。
- 子窗口发送。
- `SendNotifyMessage`。
- `keybd_event`。
- 扫描码实验。
- 编号 2、9、13 等历史方法编号。
- 无法从界面触发的旧函数。
- `#if 0` 和“留待以后恢复”的废弃代码。
- 已失去意义的模式兼容配置。

旧实现已经由 `v1.0`、`v2.0` 和 `v2.4` 标签保存，不需要继续保留在重构后的主代码中。

## 四、按键方式选择

### 1. 自动选择关闭

- 显示按键方式下拉框。
- 用户可以手动选择“共享消息”“按键+自动窗口”或“按键+手动窗口”。
- 下拉框变化时调用 `InputModeManager::setManualMode()` 写入模式实例。
- 每次 `executeKey()` 开始时调用模式实例的 `currentMode()`，并使用返回方式完成整个按键。

### 2. 自动选择开启

- 隐藏按键方式下拉框。
- 自动选择默认开启，软件启动时实例化模式对象并立即创建独立焦点检测线程。
- 自动选择开关调用 `InputModeManager::setAutomatic(true/false)`，独立控制焦点检测线程，与全局开关无关。
- 焦点检测线程每隔 `100ms` 检查一次游戏焦点。
- 每次检测都读取当前选择的游戏窗口；没有选择窗口或窗口不存在时跳过该轮。
- 游戏有焦点：选择“按键+手动窗口”。
- 游戏没有焦点：选择“共享消息”。
- 自动选择不会使用“按键+自动窗口”。
- 焦点结果最多可能有约 `100ms` 的检测延迟。
- 关闭自动选择时，模式管理器停止焦点线程，并立即恢复为下拉框保存的手动方式。

### 3. 游戏置顶

“游戏置顶”作为独立选项：

- 只控制游戏窗口的 `HWND_TOPMOST` 状态。
- 不持续抢焦点。
- 取消置顶、切换游戏窗口或退出程序时解除原窗口的置顶状态。
- 是否自动激活游戏由当前按键方式决定。

置顶、焦点检测和按键方式选择互相独立。

### 4. 切换游戏窗口

- 用户选择其他游戏窗口时，先自动关闭全局开关。
- 调度线程退出并完成旧窗口的 Detach后，才更新当前窗口。
- 自动模式线程始终存在，不因切换窗口而重建；后续检测自动读取新选择的窗口。

## 五、按键完整流程

### 1. 共享消息

1. 全局开关开启阶段已经完成 Attach。
2. 调用一次 `GetKeyboardState`。
3. 把目标 F 键设置为按下状态。
4. 调用一次 `SetKeyboardState`。
5. 使用 `SendMessageTimeout` 发送 DOWN。
6. 调用 `timeConfig.releaseInterval()` 获取当前释放间隔并等待。
7. 使用 `SendMessageTimeout` 直接发送 UP。
8. 不再调用 `GetKeyboardState` 或 `SetKeyboardState`，不恢复目标键状态。
9. 返回完整按键的执行结果。

### 2. 按键+自动窗口

1. 检查游戏窗口是否有焦点。
2. 没有焦点时恢复并激活游戏窗口。
3. 使用 `SendInput` 发送 KEYDOWN。
4. 调用 `timeConfig.releaseInterval()` 获取当前释放间隔并等待。
5. 使用 `SendInput` 发送 KEYUP。
6. 返回完整按键的执行结果。

### 3. 按键+手动窗口

1. 不主动操作游戏窗口焦点。
2. 使用 `SendInput` 发送 KEYDOWN。
3. 调用 `timeConfig.releaseInterval()` 获取当前释放间隔并等待。
4. 使用 `SendInput` 发送 KEYUP。
5. 返回完整按键的执行结果。

## 六、界面优化

### 1. 主界面

- 窗口内容右上角放置一个可切换的订书钉图标按钮，代替“总在最前”文字复选框。
- 鼠标悬停订书钉时显示提示：`游戏窗口置顶`。
- 游戏窗口选择。
- 扫描游戏窗口。
- 保留“修改窗口标题”功能。
- 保留“切换到游戏窗口”按钮。
- 自动选择开关。
- 自动选择关闭时显示按键方式下拉框：共享消息、按键+自动窗口、按键+手动窗口。
- 自动选择开启时隐藏按键方式下拉框，在同一位置显示当前实际方式：共享消息或按键+手动窗口。
- 自动选择开关和按键方式/实际方式区域放在原“总在最前”控件所在的位置。
- 不增加独立的运行状态文字。
- 将原“全局开关”复选框改为明显、较大的“开始/停止”按钮。
- 未运行时按钮显示“开始”，运行时显示“停止”；启动和停止过程由按钮禁用状态防止重复点击。
- F1～F10启用开关和单键间隔。
- 全局间隔。
- 运行中允许修改模式、单键间隔、全局间隔和释放间隔，后续读取立即使用新值。

### 2. 其他设置

- 释放间隔。
- 全局快捷键设置按钮；点击后弹出快捷键设置对话框，由用户自行录入和修改。
- 查看调试日志。

- 不增加高级设置折叠区域，以上控件直接放在主界面合适位置。

### 3. 快捷键

- 只增加一个全局开始/停止快捷键。
- 用户可以通过设置对话框自行修改组合键。
- 快捷键注册失败时明确提示。
- 使用 `RegisterHotKey`，不安装键盘 Hook。
- 不增加单独的紧急停止快捷键。

### 4. 状态反馈

- 运行期间锁定不能安全修改的配置项。
- 显示最近一次执行的按键。
- 显示最近一次实际采用的输入方式。
- 显示发送成功或失败，但执行失败不改变调度循环。
- 只有失败日志使用红色高亮；成功、警告、模式变化和普通日志均使用默认文字颜色。
- 调试日志只在日志窗口打开期间生成。
- 日志不写入文件，关闭窗口后销毁。
- 不增加系统托盘图标或托盘菜单。

## 七、实施顺序

1. 基于当前版本建立重构分支。
2. 按确认后的清单删除已验证无效的输入方式。
3. 删除缺省技能的界面、配置和调度逻辑。
4. 抽离游戏窗口管理、时间配置管理和按键启用配置管理。
5. 定义 `IKeyExecutor` 和统一的按键请求、结果接口。
6. 实现三个独立按键执行器实例以及 `KeyExecutionService`。
7. 重写只负责时序的调度线程。
8. 实现独立的 `InputModeManager` 以及默认开启的100ms焦点检测线程。
9. 实现全局开关统一控制Attach、调度线程和Detach的会话流程。
10. 重新实现游戏置顶、窗口切换自动停止和窗口激活逻辑。
11. 精简主界面，重排模式、置顶和开始/停止控件。
12. 增加可由用户配置的全局开始/停止快捷键。
13. 验证动态配置、模式切换、前后台、置顶、最小化、高频按键和真实输入场景。
14. 生成 32 位静态单文件 Windows 版本。
15. 实机验证通过后，将重构版本发布为新的正式版本。
